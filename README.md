# Просто! - Платформа для службы доставки

Платформа для службы доставки с поддержкой различных ролей пользователей, управления заказами, исполнителями и автопарками.

## 🚀 Технологии

- **Frontend**: Next.js 14 (App Router), React, TypeScript
- **Backend**: Supabase (PostgreSQL, Auth, Realtime)
- **Карты**: Leaflet
- **Стили**: Tailwind CSS
- **Состояние дашборда**: React Context (`useDashboardUser`)
- **Валидация**: Zod

## 📋 Предварительные требования

- Node.js 18+ и npm/yarn
- Аккаунт Supabase (уже настроен)
- Аккаунт GitHub (уже настроен)

## 🛠️ Установка и запуск

### 1. Установка зависимостей

```bash
npm install
```

### 2. Настройка переменных окружения

Убедитесь, что файл `.env.local` содержит:

```env
NEXT_PUBLIC_SUPABASE_URL=your_supabase_project_url
NEXT_PUBLIC_SUPABASE_ANON_KEY=your_supabase_anon_key
SUPABASE_SERVICE_ROLE_KEY=your_supabase_service_role_key
NEXT_PUBLIC_APP_URL=http://localhost:3000
```

### 3. Настройка базы данных

1. Откройте [Supabase Dashboard](https://app.supabase.com)
2. Перейдите в **SQL Editor**
3. Выполните миграции по порядку:
   - `001_initial_schema.sql` - Создание таблиц
   - `002_seed_regions.sql` - Добавление регионов Беларуси
   - `003_functions.sql` - Функции для работы с заказами
   - `004_rls_policies.sql` - Политики безопасности (RLS)

### 4. Запуск проекта

```bash
npm run dev
```

Откройте [http://localhost:3000](http://localhost:3000) в браузере.

## 👥 Роли пользователей

- **customer** - Заказчик (бары, рестораны, магазины)
- **client** - Клиент-получатель
- **driver** - Исполнитель (водитель)
- **fleet** - Автопарк
- **admin** - Администратор
- **superadmin** - Суперадмин

## 📊 Статусы заказов

- **searching_courier** - Ищем курьера
- **courier_coming** - Курьер едет к вам
- **courier_delivering** - Курьер доставляет заказ
- **completed** - Заказ завершен
- **cancelled** - Отменен

## 🗺️ Регионы

Приложение поддерживает 6 областей Беларуси:
- Минск
- Минская область
- Брестская область
- Витебская область
- Гомельская область
- Гродненская область
- Могилевская область

## Проверка сессий и push-уведомлений

```bash
node --test tests/*.test.cjs
npm run type-check
npm run lint
npm run build
```

Тесты используют подмену Supabase и push-провайдера: не меняют базу и не отправляют уведомления.
Middleware обновления сессии находится в корневом `middleware.ts`.
Для серверной рассылки нужны `SUPABASE_SERVICE_ROLE_KEY`, `NEXT_PUBLIC_VAPID_PUBLIC_KEY`
и `VAPID_PRIVATE_KEY`; опциональный `VAPID_SUBJECT` — контактный HTTPS URL или mailto.
Без VAPID-ключей API возвращает 503. Заказ при этом остаётся созданным.
Подписки доступны привилегированному клиенту только на сервере после проверки роли
и создателя заказа. Общая рассылка предназначена для публичных заказов в поиске курьера,
исключает отказавшихся водителей и не требует расширения RLS-политик.
После размещения нужно проверить вход с обновлением сессии и доставку push на тестовом
аккаунте водителя с разрешёнными уведомлениями. Мок-тесты не подтверждают реальную доставку.

## Конкурентные операции заказов (миграция 118)

`118_atomic_order_acceptance_and_payment.sql` заменяет принятие заказа, обработку оплаты
и триггер оплаты одной транзакцией. Повторный успешный платёж не создаёт начисление,
а сброс оплаченного заказа запрещён. Исторические дубли не удаляются автоматически.
Если у неоплаченного заказа уже есть credit, операция требует сверки вместо повторного начисления.

Регрессионная проверка использует отдельный временный PostgreSQL с минимальной схемой
и реальными SQL-функциями; не подключается к Supabase. Требуется установленный PostgreSQL:

```bash
python3 tests/order-concurrency.py
# Если pg_config отсутствует в PATH:
PG_BIN=/opt/homebrew/opt/postgresql@15/bin python3 tests/order-concurrency.py
```

Проверяются параллельное принятие, повторные/параллельные оплаты, оплата организацией,
баланс при оплате разных заказов, задолженность и откат при ошибке начисления.
