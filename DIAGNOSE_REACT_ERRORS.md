# Диагностика ошибок React #425, #418, #423

## Шаг 1: Проверьте, применена ли миграция 055

Выполните скрипт `VERIFY_MIGRATION_055.sql` в Supabase SQL Editor. Это проверит:
- Применена ли миграция
- Правильно ли работают функции
- Нет ли рекурсивных политик

## Шаг 2: Расшифруйте ошибки React

Ошибки React #425, #418, #423 - это минифицированные ошибки. Чтобы увидеть полное сообщение:

1. Откройте браузер в режиме разработки (не production)
2. Или добавьте в код:
```javascript
if (process.env.NODE_ENV === 'development') {
  // Ошибки будут показаны полностью
}
```

## Шаг 3: Возможные причины ошибок

### Ошибка #425
Обычно связана с проблемами рендеринга или обновления состояния в React компонентах.

**Проверьте:**
- Нет ли бесконечных циклов в `useEffect`
- Правильно ли обрабатываются асинхронные операции
- Нет ли проблем с зависимостями в хуках

### Ошибка #418
Обычно связана с проблемами в `useEffect` или других хуках.

**Проверьте:**
- Зависимости в `useEffect` - не вызывают ли они бесконечные циклы
- Правильно ли очищаются подписки и таймеры
- Нет ли проблем с асинхронными операциями

### Ошибка #423
Обычно связана с проблемами в компонентах при обновлении состояния.

**Проверьте:**
- Нет ли попыток обновить состояние после размонтирования компонента
- Правильно ли обрабатываются ошибки в async функциях

## Шаг 4: Проверьте консоль браузера

Откройте DevTools (F12) и проверьте:
1. **Console** - полные сообщения об ошибках
2. **Network** - не возвращают ли API запросы ошибки 500
3. **React DevTools** - нет ли проблем с компонентами

## Шаг 5: Временное решение

Если ошибки связаны с обновлением местоположения:

1. Убедитесь, что миграция 055 применена
2. Проверьте, что API `/api/driver/update-location` работает корректно
3. Временно отключите автоматическое обновление местоположения, если проблема критична

## Шаг 6: Получите полные ошибки

Чтобы увидеть полные ошибки React:

1. Запустите приложение в режиме разработки:
```bash
npm run dev
```

2. Или проверьте консоль браузера - там должны быть полные сообщения об ошибках

## Что делать дальше

1. **Примените миграцию 055** (если еще не применена)
2. **Выполните VERIFY_MIGRATION_055.sql** для проверки
3. **Проверьте консоль браузера** для полных сообщений об ошибках
4. **Сообщите полные ошибки**, чтобы можно было точно определить проблему
